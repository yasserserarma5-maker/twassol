# Twassol — واجهة عربية تعمل على الهاتف

## الملفات
- `index.html`: الواجهة وكل JavaScript في ملف واحد.
- `schema.sql`: الجداول والصلاحيات وقواعد الإشعارات وحاوية الصور.

## 1) إنشاء قاعدة البيانات والخادم
1. افتح https://supabase.com من المتصفح وسجّل الدخول.
2. أنشئ مشروعًا جديدًا واحفظ كلمة مرور قاعدة البيانات في مكان آمن.
3. افتح مشروعك ثم SQL Editor > New query.
4. افتح `schema.sql` وانسخ محتواه كاملًا إلى محرر SQL، ثم اضغط Run.
5. من Project Settings / Connect أو API انسخ Project URL والمفتاح العام `Publishable key` (أو anon public key القديم).
6. لا تستخدم `service_role` أو `secret key` داخل HTML؛ هذه مفاتيح سرية ممنوع نشرها.
7. في `index.html` ابحث عن `SUPABASE_URL` و`SUPABASE_KEY` واستبدل النصين بقيم مشروعك.

## 2) إعداد تسجيل الحساب
في Supabase > Authentication > URL Configuration، بعد نشر الموقع أضف رابط موقعك إلى Site URL وRedirect URLs.
للتجربة الأولية، قد تحتاج إلى تعطيل تأكيد البريد من Authentication > Providers > Email؛ الأفضل إبقاؤه مفعّلًا عندما يكون البريد الإلكتروني متاحًا.

## 3) نشر الموقع من Android
الطريقة الأسهل عبر GitHub وCloudflare Pages:
1. أنشئ حسابًا على https://github.com ثم مستودعًا جديدًا باسم `twassol`.
2. ارفع `index.html` إلى جذر المستودع (يمكن إنشاء الملف مباشرة من واجهة GitHub في المتصفح).
3. افتح https://dash.cloudflare.com ثم Workers & Pages > Create > Pages > Connect to Git.
4. اختر مستودع `twassol`. للموقع الثابت لا تحتاج إلى إطار عمل؛ اجعل Build command فارغًا أو `exit 0`، ومجلد الإخراج `/` أو المجلد الذي يحتوي `index.html` حسب واجهة الإعداد.
5. اضغط Deploy. ستحصل على رابط مثل `https://اسم-مشروعك.pages.dev`.
6. أضف الرابط إلى Supabase Authentication > URL Configuration.
بديل: Cloudflare Pages يدعم رفع ملفات ثابتة مباشرة عبر Direct Upload/Drag and drop؛ راجع الدليل الرسمي لأن خيارات لوحة التحكم قد تتغير.

## 4) جرّب
- افتح رابط الموقع، أنشئ حسابًا، ثم جرّب منشورًا وتعليقًا وإعجابًا.
- اختبر بحساب ثانٍ أو متصفح آخر للتأكد من ظهور المحتوى بين المستخدمين.
- إذا ظهر خطأ في الصلاحيات، تأكد أنك نفذت `schema.sql` كاملًا وأنك تستخدم المفتاح العام الصحيح.

## تنبيهات مهمة
- هذه نسخة أولية قابلة للتجربة وليست منصة إنتاجية مدققة أمنيًا.
- الصور عامة عبر روابطها؛ لا ترفع صورًا خاصة أو حساسة.
- الإشعارات داخل الموقع وليست إشعارات دفع للهاتف عندما يكون الموقع مغلقًا.
- بحث المستخدمين متاح للمستخدمين المسجلين. صفحة الملف الشخصي تحفظ البيانات والصورة.
- لا تنشر أي مفاتيح سرية، ولا تضع مفتاح `service_role` في `index.html`.
- خذ نسخة احتياطية من البيانات دوريًا. الخدمات المجانية لها حدود وقد تتغير شروطها.
